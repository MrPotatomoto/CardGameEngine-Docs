Sound Hooks

Map any GameEvent type to an audio clip pool using ScriptableObject assets. GameAudioService listens to the EventBus and fires a callback whenever a matching event is published — your audio manager decides how to play it.

Overview

The sound hook system consists of three types:

  • AudioEventDefinition — a ScriptableObject describing a sound: a pool of clips (one picked at random each play), volume, pitch with optional variance, loop flag, and 3-D spatialization settings.
  • GameAudioProfile — a ScriptableObject containing an ordered list of SoundTriggerRules, each pairing a game-event type name with an AudioEventDefinition.
  • GameAudioService — a runtime service (not a MonoBehaviour) that subscribes to the EventBus and invokes your playback callback whenever a rule matches. Dispose it when the session ends.

The service is presentation-layer agnostic: it resolves which audio event to play, then hands the definition to a callback. Your AudioSource management, pooling, and 3-D positioning remain entirely in your project code.

AudioEventDefinition

Create via Card Game Engine → Audio → Audio Event.

FieldDefaultDescription
Clips—One or more AudioClips. A random clip is chosen each play for natural variation.
Volume1.0Playback volume (0–1).
Pitch1.0Base playback pitch. Values below 1 slow the clip; above 1 speed it up.
Pitch Variance0.0Random offset applied each play: final pitch = Pitch ± variance. Try 0.05–0.1 for a natural feel.
LoopfalseWhether the clip loops. Useful for ambient tracks.
Spatial Blend0.00 = fully 2-D, 1 = fully 3-D. Keep at 0 for UI and card sounds.
Min Distance1Distance at which audio plays at full volume (3-D only).
Max Distance500Distance at which audio is inaudible (3-D only).

At runtime, read the resolved values from the definition's properties:

C#
AudioClip clip = def.Clip;    // random pick from the pool each call
float volume   = def.Volume;
float pitch    = def.Pitch;   // base + random variance; call each play

GameAudioProfile

Create via Card Game Engine → Audio → Audio Profile. Add SoundTriggerRule entries in the Inspector:

FieldDescription
Game Event Type NameFully-qualified C# type name of the GameEvent that triggers playback, e.g. CardGameEngine.TurnStartedEvent. Using a base type matches all subtypes.
Audio EventThe AudioEventDefinition to play when this rule matches.

Multiple rules may match the same event — all matching definitions fire in list order. Use a base type (e.g. CardGameEngine.CardStateEvent) to catch every event in a hierarchy with one rule.

GameAudioService

Create a GameAudioService when a game session starts and dispose it when the session ends:

C#
// In your game-session controller:
private GameAudioService _audioService;

void StartSession(GameContext context, GameAudioProfile profile)
{
    _audioService = new GameAudioService(
        context.EventBus,
        profile,
        PlayAudio);          // your callback
}

void EndSession()
{
    _audioService?.Dispose();
    _audioService = null;
}

// Your playback callback — called on the Unity main thread.
void PlayAudio(AudioEventDefinition def)
{
    var src = _audioSourcePool.Get();
    src.clip         = def.Clip;
    src.volume       = def.Volume;
    src.pitch        = def.Pitch;
    src.loop         = def.Loop;
    src.spatialBlend = def.SpatialBlend;
    src.Play();
}
Type names in each rule are resolved to System.Type objects once at construction time, so the per-event matching loop is allocation-free during play. An editor warning is logged for any rule whose type name cannot be resolved — check the fully-qualified name if you see unexpected silence.
