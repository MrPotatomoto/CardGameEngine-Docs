Scry

Peek the top N cards of any zone and reorder them — with UI hooks via the event bus.

Overview

Scry lets a player look at the top cards of a zone and decide: keep them on top, put them on the bottom, or a mix of both. The implementation is split across three pieces:

  • ScryEffect — drives the mechanic; peeks cards, fires events, reorders the zone.
  • ScryState — carries the peeked cards and lets the player (or UI) commit a decision.
  • ScryStartedEvent / ScryCompletedEvent — the event bus hooks for UI integration.

ScryEffect

C# — Constructor 
var effect = new ScryEffect(
    source:     effectSource,
    controller: castingPlayer,
    zone:       deck,
    count:      2          // peek the top 2 cards
);

Resolution flow

  1. Peeks the top count cards (clamped to zone size). If the zone is empty, returns Fizzled.
  2. Creates a ScryState holding the peeked cards.
  3. Publishes ScryStartedEvent carrying the state and the scrying player.
  4. If any subscriber called state.Commit(), uses the committed top/bottom piles to reorder.
  5. If no subscriber committed, applies the default: all peeked cards returned to the top in their original order.
  6. Publishes ScryCompletedEvent with the final count.

ScryState

Passed via ScryStartedEvent. Your UI layer calls Commit() once the player has made their decision.

MemberDescription
PeekedCardsThe cards that were revealed. Read-only.
IsCommittedtrue after Commit() has been called.
TopPileCards to place back on top, in order. Only valid after commit.
BottomPileCards to place on the bottom, in order. Only valid after commit.
Commit(top, bottom)Records the player's decision. Idempotent — subsequent calls are no-ops.

Connecting your UI

Subscribe to ScryStartedEvent before calling Execute(). Since event handlers are called synchronously, you can show your modal and call Commit() within the handler (for synchronous UIs) or store the state and commit later (for async UIs — see the note below).

Synchronous UI (e.g., automated tests / AI)

C# — Synchronous subscriber 
context.EventBus.Subscribe<ScryStartedEvent>(e =>
{
    // AI decision: always keep peeked cards on top
    e.State.Commit(
        topPile:    e.State.PeekedCards,
        bottomPile: System.Array.Empty<CardInstance>()
    );
});

new ScryEffect(source, player, deck, 2).Execute(context);

Async UI (Unity coroutine / UI Toolkit)

C# — Async pattern 
ScryState pendingState = null;

context.EventBus.Subscribe<ScryStartedEvent>(e =>
{
    pendingState = e.State;
    scryModal.Show(e.State.PeekedCards);  // open your UI
});

// ... in your UI callback when the player confirms:
void OnPlayerConfirmedScry(CardInstance[] top, CardInstance[] bottom)
{
    pendingState?.Commit(top, bottom);
    pendingState = null;
    scryModal.Hide();
}

// ScryEffect.Execute() will use the default resolution if Commit() hasn't been
// called by the time the handler returns. For true async UI, drive ScryEffect
// as a coroutine and await the commit before advancing resolution.
Default resolution: If no subscriber calls Commit() before the ScryStartedEvent handler returns, all peeked cards are placed back on top in their original order. This is safe for automated resolution and unit tests.

Zone layout after Scry

After ScryEffect resolves, the zone is reordered as:

  1. Top pile — committed top cards, in the order you specified (index 0 = very top).
  2. Non-scried cards — the remaining cards that were not peeked, in their original order.
  3. Bottom pile — committed bottom cards, in the order you specified.
