Spectator Mode

A spectator receives periodic full-state snapshots from the host and restores them locally — no action-sending, no game-state authority. Wire OnSnapshotApplied to refresh your board UI after each update.

Overview

SpectatorSession is a thin MonoBehaviour that sits on top of IGameTransport. It listens for StateSnapshot and SpectatorSnapshot messages from the host and calls GameSerializer.RestoreSnapshot() to bring a local GameContext up to date. All other message types (actions, chat, ping) are silently ignored.

Because the spectator receives full snapshots (not deltas), it is always eventually consistent — the view may lag by up to one snapshot interval but is never corrupted by a missed message.

Setup

  1. Create a GameContext for the spectator using the same GameDefinition as the live match — zones and players must exist for the snapshot restore to populate correctly.
  2. Create or obtain an IGameTransport connected to the host's session.
  3. Attach SpectatorSession to a scene object and call Initialise.
  4. Wire OnSnapshotApplied to trigger a full board-UI refresh.
C#
// After constructing a read-only GameContext and connecting the transport:
spectatorSession.Initialise(transport, spectatorContext);

// Refresh the board every time a snapshot arrives.
spectatorSession.OnSnapshotApplied.AddListener(boardUI.RefreshAll);

Events

EventPayloadDescription
OnSnapshotApplied—Fired after each snapshot is successfully applied. Use to refresh board UI.
OnHostDisconnected—Fired when the host transport disconnects.
OnErrorstringFired on transport errors or snapshot parse failures.

Diagnostic properties

C#
// How many snapshots have been applied since Initialise().
int count = spectatorSession.SnapshotCount;

// UTC time of the most recently applied snapshot.
DateTime last = spectatorSession.LastSnapshotTime;

Snapshot frequency

The host controls how often snapshots are sent via NetworkGameSession's Snapshot Interval Inspector field (default: 1 second). The spectator session has no control over this. Lower intervals give a more responsive view at the cost of bandwidth; for tournament streaming consider 0.5–1 s.

For a smoother spectator experience, drive UI animations from the local EventBus of the spectator's GameContext. Because RestoreSnapshot publishes events as it moves cards between zones, zone-transition animations will trigger automatically — you only need to handle the final board refresh in OnSnapshotApplied.
