Win Conditions

Inspector-configurable rules that determine when and how a game ends. Stack multiple conditions to support simultaneous elimination, alternative win states, and draws.

Overview

Win conditions sit at the top of the game loop. Before each turn begins, GameBootstrapper calls IsGameOver(context). Your override evaluates each WinConditionDefinition in order — the first one that fires stops the loop and records the winner.

Because conditions are ScriptableObject assets, they can be mixed and matched in the Inspector without touching C#. Create a condition asset, configure it, and add it to your GameDefinition's Win Conditions array.

Evaluation order matters. Conditions are checked in the order they appear in the array. If you have both an "alternative win" condition and a "last player standing" condition, put the alternative win first so it fires before the fallback.

WinConditionDefinition

All win conditions subclass this abstract ScriptableObject and implement a single method:

C# — WinConditionDefinition contract 
public abstract class WinConditionDefinition : ScriptableObject
{
    // Return true  → game is over; set winner to the winning player.
    // Return true  → draw if winner is null (zero survivors).
    // Return false → game continues.
    public abstract bool Evaluate(GameContext context, out Player winner);
}
ParameterDescription
contextLive game state. Read context.Players, zones, stats, flags — anything needed to determine the outcome.
winner (out)Set to the winning Player, or null for a draw. Only meaningful when the method returns true.

LastPlayerStandingWinCondition

The built-in condition for the most common game-over rule: the last player who hasn't been eliminated wins.

Create via Create → Card Game Engine → Win Conditions → Last Player Standing. No Inspector fields to configure.

2+ survivors

Returns false — the game continues.

Exactly 1 survivor

Returns true, winner = that player.

0 survivors (draw)

Returns true, winner = null. Fires when all remaining players are eliminated in the same SBA pass.

Player.IsEliminated

LastPlayerStandingWinCondition (and any custom condition checking survivors) reads player.IsEliminated — a simple boolean on the Player object.

This flag is not set by the engine automatically. Your bootstrapper is responsible for setting it when a PlayerEliminatedEvent is received. NoCodeBootstrapper does this for you:

C# — How NoCodeBootstrapper tracks eliminations 
// In OnGameSetupComplete — subscribes once at game start
Context.EventBus.Subscribe<PlayerEliminatedEvent>(e =>
{
    e.Player.IsEliminated = true;
    _onPlayerEliminated.Invoke(e.Player);
});

If you're writing a custom bootstrapper, add a similar subscription. The event is fired by PlayerEliminationEffect, which is itself triggered by PlayerEliminationSBA when a watched stat hits the elimination threshold.

Typical elimination pipeline:
PlayerEliminationSBA detects 0 life → fires PlayerEliminationEffect → fires PlayerEliminatedEvent → bootstrapper sets player.IsEliminated = true → LastPlayerStandingWinCondition sees one survivor → game over.

Wiring up in GameDefinition

Add condition assets to the Win Conditions array of your GameDefinition. NoCodeBootstrapper evaluates them in order each time IsGameOver is called:

C# — How NoCodeBootstrapper evaluates conditions 
protected override bool IsGameOver(GameContext context)
{
    foreach (var condition in _gameDefinition.WinConditions)
    {
        if (condition.Evaluate(context, out var winner))
        {
            _winner = winner;
            return true;
        }
    }
    return false;
}

For a custom bootstrapper, implement the same pattern inside your IsGameOver override, or call each condition manually.

Writing a custom win condition

Subclass WinConditionDefinition, add any Inspector fields you need, and implement Evaluate. Below is a condition that ends the game when any player assembles a three-card combo in their hand:

C# — ComboWinCondition example 
using UnityEngine;
using CardGameEngine;

[CreateAssetMenu(menuName = "My Game/Combo Win Condition")]
public class ComboWinCondition : WinConditionDefinition
{
    [SerializeField] private ZoneDefinition _handZone;
    [SerializeField] private CardTemplate[] _comboPieces;

    public override bool Evaluate(GameContext context, out Player winner)
    {
        winner = null;
        if (context == null || _handZone == null || _comboPieces == null)
            return false;

        foreach (var player in context.Players)
        {
            var hand = context.ZoneManager.GetZone(_handZone, player);
            if (hand == null) continue;

            bool hasAllPieces = true;
            foreach (var piece in _comboPieces)
            {
                bool found = false;
                foreach (var card in hand.Cards)
                    if (card.Template == piece) { found = true; break; }

                if (!found) { hasAllPieces = false; break; }
            }

            if (hasAllPieces)
            {
                winner = player;
                return true;
            }
        }
        return false;
    }
}
Tip: Win conditions are ScriptableObjects, so they can hold references to zone definitions, card templates, stat definitions, and any other asset. This lets you configure complex conditions entirely in the Inspector without additional code.

Combining multiple conditions

You can add any number of conditions to GameDefinition.WinConditions. Common patterns:

PatternSetup
Standard + alternative win Add your alternative-win condition before LastPlayerStandingWinCondition so it takes priority.
Time limit Write a TurnLimitWinCondition that reads context.TurnNumber and awards the win to whoever has the most life (or highest stat) after N turns.
Cooperative game A condition that returns true when an objective is completed (winner = null for a team win), plus a loss condition that fires when all players are eliminated before the objective.
