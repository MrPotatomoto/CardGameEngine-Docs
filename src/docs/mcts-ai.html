MCTS AI

Replace any AI player's strategy with MctsStrategy for a significant quality bump over random or scored play. The search runs on a background thread within a configurable time budget and returns the most-visited action when time expires.

Overview

Monte Carlo Tree Search explores the game tree by repeatedly simulating random playouts from the current state and backing the results up to the root. The four phases:

  1. Selection — walk from the root, always choosing the child with the highest UCB1 score, until a leaf or partially-expanded node is reached.
  2. Expansion — add one new child node for an untried legal action.
  3. Rollout — play forward from the new node using a fast heuristic policy until a terminal state or depth limit, scoring the outcome.
  4. Backpropagation — propagate the score back up the tree, incrementing visit counts and total reward at every ancestor.

After the time budget (or iteration cap) expires, the action leading to the most-visited child is returned — visit count is more robust than raw reward as a selection criterion.

MctsConfig

Create via Card Game Engine → AI → MCTS Config and assign it when constructing MctsStrategy.

FieldDefaultDescription
Time Budget Ms500Maximum wall-clock milliseconds per priority window. The search stops when either this or Max Iterations is reached first.
Max Iterations1000Hard iteration cap regardless of time. Set to 0 to use time budget only.
Exploration Constant1.414 (√2)UCB1 exploration weight. Higher values favour unexplored branches; lower values exploit known-good lines. √2 is theoretically optimal for uniform reward distributions.
Max Rollout Depth50Maximum actions per rollout simulation. Prevents infinite-game hangs.
Rollout Pass Rate0.3Probability of passing priority at each rollout step. Higher = shorter, noisier rollouts.

Usage

C#
// Assign MctsStrategy to an AIPlayer.
var config   = Resources.Load<MctsConfig>("MyMctsConfig");
var strategy = new MctsStrategy(config);
aiPlayer.Strategy = strategy;

// Or use default parameters without a config asset:
aiPlayer.Strategy = new MctsStrategy();

MctsStrategy implements IAIStrategy, so it plugs directly into any AIPlayer that already uses the existing strategy interface — no other wiring required.

Threading model

The MCTS loop runs on a background Thread via Task.Run. The live GameContext is never mutated during the search — a GameSerializer.SnapshotToJson() call captures state on the main thread at the start of each priority window, and the background thread works entirely from that snapshot.

The default rollout uses a heuristic score (casting a card ≈ 0.7, activating an ability ≈ 0.5, passing ≈ 0.1) plus random noise rather than full game-state simulation. For higher-quality search, subclass MctsStrategy and override the Rollout method with a domain-specific evaluation function.

Tuning guidelines

GoalAdjustment
Faster decisions, lower qualityReduce Time Budget Ms or Max Iterations
Stronger play, more latencyIncrease Time Budget Ms
More exploratory (diverse) playIncrease Exploration Constant (try 2.0–3.0)
More exploitative (greedy) playDecrease Exploration Constant (try 0.5–1.0)
Deeper rolloutsIncrease Max Rollout Depth, decrease Rollout Pass Rate

Deterministic testing

C#
// Pass a seeded Random for reproducible decisions in tests.
var strategy = new MctsStrategy(config, new System.Random(42));
