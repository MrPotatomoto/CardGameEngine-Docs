Localization

Translate card names, rules text, zone names, and phase names at runtime with a single active locale table — all without touching existing assets or breaking any existing API calls.

Overview

The localization system is built around three types:

  • LocalizedString — a serializable struct that pairs a lookup key with an English fallback. Stored in fields that formerly held a plain string.
  • CardLocalizationTable — a ScriptableObject that maps keys to translated strings for one locale (e.g. French, Japanese).
  • LocalizationService — a static class that holds the active table and resolves keys at call time.

The design is opt-in and non-breaking. All existing string fields on CardDefinition, PhaseDefinition, StepDefinition, and ZoneDefinition remain unchanged. Separate key fields and Localized* properties were added alongside them. Code that references CardName, PhaseName, etc. continues to compile and run without modification.

Leave key fields empty on any asset to always display the raw fallback value. No locale table is required — the system degrades gracefully to English-only when no table is active.

Creating a locale table

Create a CardLocalizationTable asset via Card Game Engine → Localization → Localization Table. Set the Locale Code (e.g. fr, ja, zh-CN) and Locale Name (e.g. French) in the Inspector, then add entries:

FieldDescription
KeyThe lookup key. Convention: category.identifier.field, e.g. card.lightning-bolt.name.
ValueThe translated string for this locale.

A project can contain multiple locale tables — one per language. Only one table is active at a time; swap it via LocalizationService.SetLocale().

Activating a locale

Call LocalizationService.SetLocale() once at game startup, or when the player changes their language setting:

C#
// Assign a CardLocalizationTable ScriptableObject reference in the Inspector.
[SerializeField] private CardLocalizationTable _frenchTable;

void Start()
{
    LocalizationService.SetLocale(_frenchTable);
}

// To revert to raw fallback values:
LocalizationService.SetLocale(null);

Reading localized values

Every affected ScriptableObject gains a Localized* property that resolves through the active table automatically:

C#
// CardDefinition
string displayName  = card.CurrentFace.LocalizedCardName;
string displayRules = card.CurrentFace.LocalizedRulesText;
string displayFlavor = card.CurrentFace.LocalizedFlavorText;

// PhaseDefinition
string phaseName = phase.LocalizedPhaseName;

// StepDefinition
string stepName = step.LocalizedStepName;

// ZoneDefinition
string zoneName = zone.LocalizedZoneName;

When no table is active, or when the key field is empty, these properties return the original English fallback stored on the asset — exactly as before.

Using LocalizedString directly

LocalizedString is a serializable struct you can embed in your own ScriptableObjects or MonoBehaviours:

C#
[SerializeField] private LocalizedString _tooltip;

// In a UI script:
tooltipLabel.text = _tooltip.Resolve();  // or just: _tooltip (implicit string conversion)
MemberDescription
KeyThe lookup key used to find this string in the active table.
FallbackThe default (English) value shown in the Inspector and used when no table entry exists.
Resolve()Returns the translated value if the active table contains the key; otherwise returns Fallback.
implicit stringCalls Resolve() automatically wherever a plain string is expected.

LocalizationService API

MemberDescription
SetLocale(table)Activates a locale table. Pass null to revert to raw fallback values.
ActiveTableThe currently active CardLocalizationTable, or null.
ActiveLocaleCodeThe IETF language tag of the active table (e.g. "fr"), or null.
Resolve(LocalizedString)Resolves a LocalizedString struct.
Resolve(key, fallback)Resolves a raw key/fallback pair — useful when the key is stored separately.

Key naming convention

Use the pattern category.identifier.field, keeping identifiers lowercase with hyphens:

  • card.lightning-bolt.name
  • card.lightning-bolt.rules
  • card.lightning-bolt.flavor
  • phase.main.name
  • zone.graveyard.name

Consistent keys make it straightforward to export a master key list and hand it to translators.
