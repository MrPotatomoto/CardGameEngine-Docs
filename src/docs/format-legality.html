Format Legality

Define banned and restricted card lists, enforce deck size limits, and track set rotation dates — all through DeckFormatDefinition ScriptableObject assets validated by DeckDefinition.Validate().

Overview

The format legality system extends the existing DeckFormatDefinition + DeckDefinition.Validate() pipeline introduced in v5. v6.0 adds:

  • Banned cards list — cards that may not appear in any deck for this format.
  • Restricted cards list — cards limited to exactly one copy per deck (e.g. Vintage restricted list).
  • Rotation date on sets — SetDefinition now carries a RotationDate field so you can display when a set rotates and implement auto-rotation logic.

Set rotation dates

Each SetDefinition asset now has a Rotation Date field (YYYY-MM-DD format) in its Identity section. Leave it empty for sets that never rotate (eternal-legal sets).

PropertyDescription
RotationDateRotation date string in YYYY-MM-DD format. Empty when the set does not rotate.
HasRotationDatetrue when a non-empty rotation date is set.
C#
if (set.HasRotationDate)
    rotationLabel.text = $"Rotates {set.RotationDate}";
else
    rotationLabel.text = "Eternal legal";
The engine stores the rotation date as a string and does not compare it to the current calendar date automatically. To enforce automatic set rotation (e.g. filter out sets whose rotation date has passed), compare RotationDate to DateTime.Now in your format-setup code and remove rotated sets from the DeckFormatDefinition.AllowedSets list.

Banned & restricted lists

Open any DeckFormatDefinition asset. The new Banned & Restricted header exposes two lists:

FieldDescription
Banned CardsCard templates that may not appear in any deck for this format. Takes precedence over the Restricted list — if a card is on both lists it is simply banned.
Restricted CardsCard templates limited to exactly one copy per deck. More than one copy produces a violation.

Running validation

Call DeckDefinition.Validate(format) to receive a list of every violation found. An empty list means the deck is legal:

C#
IReadOnlyList<DeckViolation> violations = myDeck.Validate(standardFormat);

if (violations.Count == 0)
{
    StartGame();
}
else
{
    foreach (var v in violations)
        ShowError(v.Description);
}

Violation types

Each DeckViolation carries a Type (a DeckViolationType enum value), a human-readable Description, and (where applicable) the offending OffendingTemplate, ActualCount, and AllowedCount.

The validation checks run in this order:

  1. Deck size — total card count vs MinDeckSize / MaxDeckSize.
  2. Banned cards — any card on the banned list fails immediately; further copy-count checks are skipped for that card.
  3. Restricted cards — cards on the restricted list may appear at most once.
  4. Copy limit — non-restricted cards may not exceed MaxCopiesOfAnyCard.
  5. Set legality — when EnforceSetConstraints is enabled, each card must belong to an allowed set.
Violation typeMeaning
TooFewCardsDeck is below the format's minimum size.
TooManyCardsDeck exceeds the format's maximum size.
BannedCardA card on the banned list appears in the deck.
RestrictedCardExceedsLimitA restricted card appears more than once.
TooManyCopiesOfCardA non-restricted card exceeds the per-card copy limit.
CardNotInAllowedSetA card's set is not in the format's allowed-set list.

Helper methods on DeckFormatDefinition

C#
// Check a single card without running a full deck validation:
bool banned     = format.IsBanned(cardTemplate);
bool restricted = format.IsRestricted(cardTemplate);
bool setOk      = format.IsSetAllowed(set);

// Read the lists:
IReadOnlyList<CardTemplate> banned     = format.BannedCards;
IReadOnlyList<CardTemplate> restricted = format.RestrictedCards;
IReadOnlyList<SetDefinition> allowed   = format.AllowedSets;
IsBanned and IsRestricted use reference equality (same ScriptableObject asset), so the CardTemplate in your deck entries must be the same asset reference as the one in the format lists — not a different asset for the same card.
