Puzzle Mode

Define self-contained scenarios entirely in the Inspector: set a pre-built board state via a JSON snapshot, author win and loss conditions as ScriptableObject assets, add an optional turn limit and hint chain — then hand control to PuzzleRunner.

Overview

The puzzle system has three layers:

  • PuzzleDefinition — a ScriptableObject describing the scenario (board snapshot, conditions, turn limit, hints, player decks).
  • PuzzleCondition — an abstract ScriptableObject base. Concrete subtypes (ZoneCardCountCondition, PlayerStatCondition) evaluate a GameContext and return true/false.
  • PuzzleRunner — a MonoBehaviour that applies the snapshot, subscribes to turn events, evaluates conditions, and fires OnWin / OnLoss events your UI can handle.

PuzzleDefinition

Create via Card Game Engine → Puzzle → Puzzle Definition.

FieldDescription
Puzzle NameTitle shown on the puzzle-select screen.
DescriptionFlavour text shown before the puzzle starts.
Preview ArtSprite shown on the puzzle-select card.
Game DefinitionThe GameDefinition that sets up zones and players.
Player DecksPer-player deck assignments (index 0 = player 1, etc.).
Starting SnapshotOptional JSON string from GameSerializer.SnapshotToJson(). Restores a pre-set board state before the first turn. Leave empty for a clean board.
Win ConditionsArray of PuzzleCondition assets. The puzzle is won when any condition evaluates to true.
Loss ConditionsArray of PuzzleCondition assets. Evaluated after win conditions — simultaneous win+loss resolves as a win.
Turn LimitMaximum turns before a timeout loss. 0 = no limit.
HintsOrdered array of hint strings unlockable by the player.

PuzzleCondition assets

All condition types extend the abstract PuzzleCondition ScriptableObject. Implement your own by subclassing it and overriding Evaluate(GameContext).

ZoneCardCountCondition

Create via Card Game Engine → Puzzle → Zone Card Count Condition.

FieldDescription
ZoneThe zone definition to query.
Check Active PlayerTrue = check the active player's instance of this zone. False = look up the zone without an owner (e.g. a shared battlefield).
OperatorComparison: Equal, NotEqual, LessThan, LessThanOrEqual, GreaterThan, GreaterThanOrEqual.
Target CountThe card count to compare against.

Example: "Win when the opponent's library reaches 0 cards" — set Zone = Library, Check Active Player = false, Operator = Equal, Target Count = 0.

PlayerStatCondition

Create via Card Game Engine → Puzzle → Player Stat Condition.

FieldDescription
Check Active PlayerTrue = check the active player. False = condition is met when any non-active player satisfies it.
Resource TypeThe resource pool to read (e.g. your Life resource type asset).
Resource SubtypeOptional subtype filter (e.g. a specific mana colour). Leave null for the pool's untyped total.
OperatorComparison operator.
Target ValueThe amount to compare against.

Example: "Lose when your life reaches ≤ 0" — Check Active Player = true, Resource Type = Life, Operator = LessThanOrEqual, Target Value = 0.

PuzzleRunner

Attach PuzzleRunner alongside GameBootstrapper on your game-session root.

Setup

  1. Assign a PuzzleDefinition in the Inspector (or call LoadPuzzle(def) at runtime).
  2. Wire OnWin and OnLoss to your victory and defeat overlays.
  3. After your GameBootstrapper finishes constructing the GameContext, call StartPuzzle(context).
C#
// After GameBootstrapper.Setup() completes:
puzzleRunner.StartPuzzle(gameContext);

// Assign a puzzle at runtime before calling StartPuzzle.
puzzleRunner.LoadPuzzle(puzzleDefinition);
puzzleRunner.StartPuzzle(gameContext);

// Stop and unsubscribe (also called automatically on OnDestroy).
puzzleRunner.StopPuzzle();

Events

EventPayloadFired when
OnWinPuzzleConditionAny win condition evaluates to true. Payload is the matching condition.
OnLossPuzzleConditionAny loss condition evaluates to true, or the turn limit is exceeded. Payload is null on timeout.
OnHintUnlockedstringThe player calls UnlockNextHint() and a hint is available. Payload is the hint text.

Hints

C#
// Called by a "Hint" UI button. Returns null when all hints are exhausted.
string hint = puzzleRunner.UnlockNextHint();
if (hint != null) hintPanel.Show(hint);

Board snapshots

A starting snapshot lets you pre-place cards, set resource values, and apply counters before the puzzle's first turn. To create one:

  1. Set up the desired board state in a running game session.
  2. Call GameSerializer.SnapshotToJson(context) to capture it.
  3. Paste the resulting JSON string into the Starting Snapshot field of your PuzzleDefinition.

Leave the field empty to start from a clean board — useful for puzzles where the player draws into their solution rather than starting mid-board.

Conditions are evaluated once at StartPuzzle time (after the snapshot is applied). This means a trivial puzzle that is already solved from the starting state fires OnWin immediately — useful for tutorial demos.
