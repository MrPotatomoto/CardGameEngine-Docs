No-Code Setup

Configure and run a complete game session from the Unity Inspector using two assets — GameDefinition and NoCodeBootstrapper — without writing any C#.

Overview

The no-code path bundles the bootstrapper pattern into a pair of ready-made types:

GameDefinition

A ScriptableObject that holds every configuration value for one game variant: turn structure, zones, players, decks, win conditions, state-based actions, and opening-hand settings.

NoCodeBootstrapper

A MonoBehaviour that reads a GameDefinition at Start(), creates all zones and players, populates decks, deals opening hands, and drives the turn loop — all without any manual wiring.

For games with custom logic that can't fit in the Inspector (e.g. UI-driven mulligans, undo support, non-standard zone layouts), subclass GameBootstrapper directly and use NoCodeBootstrapper as a reference implementation.

Minimum setup

  1. Create a TurnStructureDefinition — Create → Card Game Engine → Turn Structure. Add at least one phase.
  2. Create a ZoneDefinition with IsStack = true — this is the effect-resolution stack.
  3. Create per-player zones (Library, Hand, Battlefield, Graveyard) as ZoneDefinition assets. Set IsStack = false on each.
  4. Create a GameDefinition — Create → Card Game Engine → Game Definition. Fill in Turn Structure, Stack Zone, Per Player Zones, Library Zone, Hand Zone, and Players (at least two entries).
  5. Add a Win Condition — create a Last Player Standing asset and add it to the Win Conditions array.
  6. Add NoCodeBootstrapper to a scene GameObject — Add Component → Card Game Engine → No-Code Bootstrapper. Assign your GameDefinition.
  7. Press Play.
Library and Hand Zone fields on GameDefinition are semantic shorthand. The zones must also appear in the Per Player Zones array — the dedicated fields just tell the bootstrapper which zone to use for deck population and hand dealing.

Human input — the response-queue pattern

Because the turn loop runs synchronously inside a coroutine, UI input arrives between frames. NoCodeBootstrapper uses a response queue: UI code enqueues actions any time; on the next priority window for that player, the first queued entry is dequeued and pushed to the stack.

C# — Card-click handler (attach to a CardView or button) 
[SerializeField] private NoCodeBootstrapper _bootstrapper;

public void OnCardClicked(CardInstance card)
{
    var ctx    = _bootstrapper.Context;
    var player = ctx.Players[0]; // human is player 0

    var action = ctx.PlayCardSystem.CreatePlayCardAction(card, player);
    if (action == null) return; // card can't be played right now

    // Add targets if the card requires them
    action.Stage = PendingActionStage.SelectingTargets;
    action.Targets.Add(chosenTarget);

    // Commit: pays costs and locks in the action
    var entry = action.TryCommit(ctx);
    if (entry == null) { action.Cancel(ctx); return; }

    // Hand off to the bootstrapper's response queue
    _bootstrapper.CommitAction(entry);
}

When the player has nothing to do, the priority window auto-passes. You can also call PassPriority() explicitly — useful as the target of a "Pass" button in your UI:

C# — Pass button handler 
public void OnPassButtonClicked()
{
    _bootstrapper.PassPriority();
}

AI players

Set Is Human to false in a PlayerSetupEntry and assign an AIStrategyDefinition. Two strategies are built in:

AssetBehaviourInspector fields
PassAlwaysStrategyDefinition Always passes priority — useful as a placeholder or "spectator" slot while building the game. None
RandomStrategyDefinition Picks a random legal action each priority window, with a configurable pass probability. Pass Rate (0–1 float), Seed (-1 = random)

Both are located under Create → Card Game Engine → AI. For a custom strategy, subclass AIStrategyDefinition (see AI Players).

Unity Events

NoCodeBootstrapper exposes three serialized UnityEvent<Player> fields in the Events section. Subscribe via code from other components or listen at runtime to drive UI:

EventWhen it firesPlayer argument
On Game OverOnce when all win conditions resolve and the game loop ends.The winner, or null for a draw.
On Priority GrantedEach time a human player receives priority in a priority window.The player who holds priority.
On Player EliminatedEach time a player's IsEliminated flag is set to true.The eliminated player.
C# — Subscribing to events from another component 
[SerializeField] private NoCodeBootstrapper _bootstrapper;

private void Awake()
{
    _bootstrapper._onGameOver.AddListener(OnGameOver);
    _bootstrapper._onPlayerEliminated.AddListener(OnEliminated);
}

private void OnGameOver(Player winner)
{
    if (winner != null)
        winLabel.text = $"{winner.DisplayName} wins!";
    else
        winLabel.text = "Draw!";
}

private void OnEliminated(Player player)
{
    Debug.Log($"{player.DisplayName} has been eliminated.");
}

Opening hand and mulligan

When both Library Zone and Hand Zone are set and a player's Deck is assigned, the bootstrapper automatically:

  1. Populates the library from the deck definition.
  2. Shuffles the library.
  3. Deals Opening Hand Size cards.
  4. Runs up to Max Mulligans rounds of mulligan offers (if Enable Mulligan is true).

The default mulligan behaviour is auto-keep for all players. To add UI-driven or AI-driven mulligan decisions, subclass GameBootstrapper and override the mulligan event subscription:

C# — Custom mulligan handler in a subclass 
// In your custom bootstrapper's OnGameSetupComplete override:
Context.EventBus.Subscribe<MulliganOfferedEvent>(e =>
{
    // e.State.Player    — which player was offered the mulligan
    // e.State.Round     — 0 = initial offer, 1+ = subsequent rounds
    // e.State.Cards     — the current hand contents

    if (ShouldMulligan(e.State))
        e.State.Mulligan();  // return hand, draw one fewer card
    else
        e.State.Keep();
});

Extending the bootstrapper

For anything beyond what the Inspector can express — custom undo, per-player game-object references, non-standard zone layouts — subclass GameBootstrapper directly. NoCodeBootstrapper is a practical reference for that pattern. The key overrides are:

OverridePurpose
GetTurnStructure()Return the turn structure asset.
SetupZones(context)Call ZoneManager.CreateZone / CreateStackZone.
CreatePlayers(context)Instantiate Player objects in turn order.
SetupPlayerResources(player, context)Initialize stats and grant starting resources.
OnGameSetupComplete(players)Register SBAs, subscribe to events, deal opening hands.
IsGameOver(context)Return true when a win or loss condition is met.
OnPriorityWindow(player, tc, ctx)Return true = pass, false = acted (pushed to stack).
OnGameOver()Show results screen, log outcome, clean up.
Tip: You can mix the no-code and coded approaches — use GameDefinition to hold your asset references and pass them to a custom bootstrapper subclass. This gets you the Inspector-driven configuration of GameDefinition without the limitations of NoCodeBootstrapper.
