Replay Viewer

Load a GameReplayLog JSON file in the Unity Editor and step through every action your game recorded — seeing the turn, phase, player, card, and notes for each event alongside a snapshot of the game state at the start of the session.

Overview

The Replay Viewer is an editor-only window that opens .json files produced by GameSerializer.ReplayToJson at runtime. It presents a two-panel layout:

  • Timeline (left) — a scrollable list of every recorded action, preceded by a fixed Initial State row. Click any row to select it.
  • Detail (right) — shows the full data for whichever row is selected: structured fields for an action, or zone / player / resource data for the initial state.

Open via Window → Card Game Engine → Replay Viewer. The window requires a minimum size of 700 × 450 px.

Recording replays at runtime

Attach a ReplayLogger component to your game session object before play begins. The logger listens to game events and appends an ActionRecord each time a player acts. When the session ends (or at any point during play), call:

C#
string json = GameSerializer.ReplayToJson(replayLog);
File.WriteAllText(outputPath, json);

The resulting JSON file can be opened directly in the Replay Viewer. No Unity project or asset database is required — the viewer parses the file from any path on disk.

Loading a file

Click Open… in the toolbar. A standard file-picker opens; select any .json file produced by GameSerializer.ReplayToJson. On success, the filename and total action count appear in the toolbar and the timeline populates. If the file cannot be parsed, a dialog shows the error message from the parser.

The viewer holds the log in memory only — it does not import the file as a Unity asset. You can open logs from outside your project folder (e.g., from a build output directory or a QA report archive) without any asset-database changes.

Toolbar

◀ / ▶Step backward or forward through the (filtered) timeline one action at a time. ◀ is disabled when the Initial State row is selected; ▶ is disabled at the last action.

Timeline panel

The timeline always opens with the Initial State row at the top (outside the scroll area). Below it, action rows appear in recording order. When a turn filter is active, rows for other turns are hidden — the visible rows are renumbered in display order but the underlying indices are unchanged.

Action row layout

Each action row is 36 px tall and shows:

  • A 4 px color bar on the left edge, color-coded by action type (see table below).
  • A turn chip (e.g., T3) in the top-left.
  • The phase / step label (e.g., Main / PreCombatMain) to the right of the chip.
  • The player display name and action type on the second line.
  • The card template ID (if the action involves a card), shown in a light blue tint.

Click any row to select it; the detail panel updates immediately. The selected row highlights in blue.

Detail panel

The right panel shows different content depending on which timeline row is selected.

Initial State detail

Selecting the Initial State row shows a structured breakdown of the GameSnapshot captured at recording start:

SectionFields shown
Initial StateCapturedAt timestamp, Turn number, Active player name, Priority player name.
PlayersDisplay name for every player in the snapshot.
ZonesZone definition name, owner display name (or "Shared"), and card count for every zone captured in the snapshot.
StackController name and description for each stack entry (only shown when the stack is non-empty at capture time).
ResourcesFor each resource pool: player name, resource type name, and a formatted list of subtype amounts.

Action detail

Selecting an action row shows the full ActionRecord fields:

FieldDescription
TurnTurn number when the action was recorded.
PhasePhase name (e.g., Main, Combat).
StepStep name within the phase, if applicable (e.g., DeclareAttackers). Omitted when empty.
PlayerDisplay name of the acting player.
TypeHuman-readable action type string.
Template IDThe CardTemplateId of the card involved, if any.
Target IDThe TargetTemplateId, if the action targeted a specific card.
NotesFree-form text logged by the game (word-wrapped). Only shown when non-empty.

Typical workflow

  1. Enable ReplayLogger in your game session. Run a match (in the Editor or a standalone build).
  2. After the match ends, the log JSON is written to disk by your session code calling GameSerializer.ReplayToJson.
  3. In the Editor, open Window → Card Game Engine → Replay Viewer.
  4. Click Open… and select the log file.
  5. Click the Initial State row to confirm the starting zone counts and resource pools look correct.
  6. Scroll through the timeline or use ▶ to step action by action. Use the turn slider to focus on a particular turn.
  7. Click any action row to examine the full detail — phase, player, card, and notes — in the right panel.
Investigating bugs: When a player reports unexpected behavior, ask them to share the replay JSON. Load it in the Replay Viewer, filter to the reported turn, and step through actions one by one to pinpoint the first incorrect transition.
