Deck Builder UI

A fully wired runtime deck editor in four components: browse your collection, manage the current deck, filter by name or type, and validate against format rules — all in a single prefab generated by a one-click Editor utility.

Overview

The deck builder is composed of four MonoBehaviour components that you combine in a Canvas hierarchy:

  • DeckBuilderController — the orchestrator. Owns the deck state (Dictionary<CardTemplate, int>), drives live validation, and exposes Open(), Save(), and ClearDeck().
  • DeckBuilderSearch — a name-filter input and type-toggle bar that fires an OnFilterChanged event whenever either filter changes.
  • CardCollectionEntry — one tile in the browsable collection grid. Shows the card name, how many copies are in the deck, and Add/Remove buttons.
  • DeckSlotEntry — one row in the current-deck list. Shows the card name, copy count, and a Remove button.

A prefab builder (Card Game Engine → Create → Deck Builder Prefab) generates a complete 1200×800 Canvas wired and ready to use.

Public API

C#
// Open the builder with an existing deck (or null for a blank deck).
deckBuilderController.Open(existingDeck);

// Add / remove a card programmatically.
deckBuilderController.AddCard(cardTemplate);
deckBuilderController.RemoveCard(cardTemplate);

// Clear all cards.
deckBuilderController.ClearDeck();

// Save the current deck back to a DeckDefinition asset.
deckBuilderController.Save();

// UnityEvent fired after a successful save.
deckBuilderController.OnDeckSaved.AddListener(deck => Debug.Log($"Saved: {deck.DeckName}"));

DeckBuilderSearch

Attach to a panel containing a TMP_InputField and one or more Toggle components. Configure the type-filter array in the Inspector to pair each toggle with a CardType value.

C#
// Subscribe to filter changes (DeckBuilderController does this for you).
search.OnFilterChanged += filter =>
{
    foreach (var entry in collectionEntries)
        entry.gameObject.SetActive(filter(entry.Template));
};

// Check a single template manually.
bool passes = search.Passes(template);

// Reset all filters.
search.ClearAll();

CardCollectionEntry & DeckSlotEntry

Both entry types are [RequireComponent(typeof(Button))]. Wire them by calling Bind() on instantiation:

C#
// Collection grid tile.
entry.Bind(
    template,
    copiesInDeck,
    onAdd:    t => controller.AddCard(t),
    onRemove: t => controller.RemoveCard(t));

// Deck list row.
slotEntry.Bind(
    template,
    copyCount,
    onRemove: t => controller.RemoveCard(t));

// Refresh the count badge after an add/remove.
entry.RefreshCount(newCount);

Live validation

DeckBuilderController validates the deck after every add/remove. It builds a temporary DeckDefinition ScriptableObject in memory (never written to disk) and calls DeckDefinition.Validate(format), which checks:

  1. Minimum and maximum deck size.
  2. Per-card copy limit.
  3. Set legality (cards from sets not allowed by the format).
  4. Banned cards.
  5. Restricted cards (max 1 copy allowed).

Each violation is shown as a labelled row in the Violation Container. The Save button remains disabled until all violations are cleared (configurable).

Leave Format null to skip validation entirely — useful for free-build modes or early prototyping.

Prefab builder

Run Card Game Engine → Create → Deck Builder Prefab to generate Assets/DeckBuilderPrefab.prefab. The resulting hierarchy contains:

  • CollectionPanel — DeckBuilderSearch (name input + type toggles) + a ScrollRect with a GridLayoutGroup content rect for collection entries.
  • DeckPanel — deck name/count TMP labels + a ScrollRect with a VerticalLayoutGroup for deck entries + a violations list.
  • ActionBar — Save and Clear buttons in a HorizontalLayoutGroup.

All DeckBuilderController slots are pre-wired via SerializedObject. Drop in your own entry prefabs and format asset to go live.
