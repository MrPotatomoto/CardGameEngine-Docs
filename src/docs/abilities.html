Abilities

Give cards automatic reactions and player-activated powers using the WHEN / IF / THEN ability model.

Overview

Every card ability in Card Game Engine is one of two kinds:

  • Triggered abilities — automatic reactions to game events. "Whenever a creature enters the battlefield, draw a card."
  • Activated abilities — player-pays-a-cost actions. "{T}: add one mana."

Both are configured entirely in the Inspector as ScriptableObject assets, then attached to a CardDefinition via its Triggered Abilities or Activated Abilities lists. No subclassing needed for typical abilities.

Triggered Abilities

A TriggeredAbilityDefinition has three parts — it is literally a WHEN / IF / THEN:

WHEN — EventFilterDefinition

Which game event causes this ability to trigger. Examples: CardEnteredZoneEventFilter, CardDamagedEventFilter, TransferTagEventFilter.

IF — ConditionDefinition (optional)

Extra guard checked after the event matches. Examples: ZoneContainsCondition, AndCondition, NotCondition. Leave empty to trigger on the event match alone.

THEN — EffectDefinition

What happens when the ability resolves. Any EffectDefinition asset — DrawCardEffectDefinition, DealDamageEffectDefinition, SequenceEffectDefinition, etc.

Creating a triggered ability

  1. Right-click in the Project window → Create → Card Game Engine → Abilities → Triggered Ability.
  2. The custom inspector shows three colour-coded sections. Click Create & Assign next to the WHEN field to pick an event filter type from a context menu — the asset is created in the same folder and linked automatically.
  3. Optionally set the IF condition.
  4. Click Create & Assign next to THEN and pick an effect type.
  5. Toggle Bypasses Stack if this ability should resolve instantly without players being able to respond.
  6. Drag the finished ability into the Triggered Abilities list on your CardDefinition.
Tip: Error banners appear in the inspector when WHEN or THEN is unassigned. An ability with no event filter never fires; one with no effect does nothing.

Runtime lifecycle

When a card with triggered abilities enters an active zone (any zone where ZoneDefinition.AbilitiesActive is true), your game should call TriggerRegistry.Register(ability, card, controller) for each ability. When the card leaves, call TriggerRegistry.UnregisterAll(card).

On every published event, TriggerRegistry calls ShouldTrigger on every registered ability. If it returns true, an ActiveTrigger is queued. The game state machine drains the trigger queue before each priority grant, calling CreateEffect() to instantiate the IEffect and executing it.

C# — Registering card abilities 
// When a card enters the battlefield, register its triggered abilities.
context.EventBus.Subscribe<CardEnteredZoneEvent>(e =>
{
    if (e.EnteredZone != battlefield) return;

    foreach (var ability in e.Card.Definition.TriggeredAbilities)
        context.TriggerRegistry.Register(ability, e.Card, e.Card.Controller);
});

// When it leaves, clean up.
context.EventBus.Subscribe<CardLeftZoneEvent>(e =>
{
    if (e.LeftZone != battlefield) return;
    context.TriggerRegistry.UnregisterAll(e.Card);
});

Activated Abilities

A ActivatedAbilityDefinition describes a "[Cost]: [Effect]" ability. The player pays one or more costs voluntarily to produce an effect.

Parts of an activated ability

  • Costs (AbilityCost[]) — all must be payable and are all paid atomically. See Ability Costs below.
  • Effect (EffectDefinition) — what happens when the ability resolves.
  • Timing (ActivationTiming) — AnyTime (instant speed) or SorcerySpeed (your main phase, empty stack only).
  • Bypasses Stack — if true, resolves immediately; players cannot respond. Most mana abilities use this.

Creating an activated ability

  1. Right-click → Create → Card Game Engine → Abilities → Activated Ability.
  2. In the COSTS section, use the reorderable list to drag existing cost assets, or click Create & Add Cost to create one in-place.
  3. In the EFFECT section, assign or create an effect.
  4. Set Timing and stack behaviour.
  5. Drag the ability into the Activated Abilities list on your CardDefinition.

Runtime flow

Your game layer calls ActivateAbilitySystem.TryActivate(card, abilityIndex, player) when a player uses an ability. The system checks timing legality and CanActivate(), pays costs via PayCosts(), then either executes immediately (if BypassesStack) or pushes a StackEntry.

C# — Activating a tap ability at runtime 
// e.g., player clicks "Use ability 0" on a card
var result = context.ActivateAbilitySystem.TryActivate(card, abilityIndex: 0, player);

if (!result.Succeeded)
    Debug.LogWarning($"Cannot activate: {result.Reason}");

Ability Costs

AbilityCost is an abstract ScriptableObject. The engine ships with several concrete types, and you can add your own by extending it.

TapCostDefinition

Requires the source card to be untapped. Taps it on payment.

Create → Card Game Engine → Costs → Tap

CompositeCostDefinition

Combines multiple costs with AND — all sub-costs must be payable and are all paid together. Use to model "{T}, Pay 2 mana" combos.

Create → Card Game Engine → Costs → Composite

Writing a custom cost

C# — SacrificeCost.cs 
using UnityEngine;
using CardGameEngine;

/// <summary>Cost: sacrifice the source card.</summary>
[CreateAssetMenu(menuName = "Card Game Engine/Costs/Sacrifice")]
public sealed class SacrificeCostDefinition : AbilityCost
{
    [SerializeField] private ZoneType _graveyardZoneType;

    public override bool CanPay(Player player, CardInstance source, GameContext context)
    {
        // Can sacrifice if the card is on the battlefield
        return source != null
            && source.CurrentZone?.Definition?.ZoneType != _graveyardZoneType;
    }

    public override bool Pay(Player player, CardInstance source,
                              EffectSource effectSource, GameContext context)
    {
        var graveyard = context.ZoneManager.GetZoneByType(_graveyardZoneType, player);
        if (graveyard == null) return false;
        return context.ZoneManager.Transfer(source, graveyard, effectSource);
    }
}

Bypasses Stack

Abilities with BypassesStack = true resolve immediately when they trigger or are activated — opponents cannot respond with instants. Use this for mana abilities and other "fast" effects that mirror real TCG rules. Leave it false for anything that should be interruptible.
