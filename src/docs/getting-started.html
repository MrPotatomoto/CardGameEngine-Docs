Getting Started

Install Card Game Engine and play your first card in under 10 minutes.

Requirements: Unity 6 (6000.0) or newer. Git must be installed on your machine for the UPM Git URL method.

Installation

The recommended method. Unity will download and lock the package at exactly v6.0.0.

  1. Open your Unity project and go to Window → Package Manager.
  2. Click the + button (top-left) → Add package from git URL…
  3. Paste the URL below and click Add.
Git URL — v6.0.0 
https://github.com/MrPotatomoto/CardGameEngine-Dev.git?path=Packages/com.cardgameengine.core#v6.0.0

To always track the latest commit on main instead, omit the version tag:

Git URL — latest 
https://github.com/MrPotatomoto/CardGameEngine-Dev.git?path=Packages/com.cardgameengine.core
Tip: Pin to a version tag in production so a future update never silently breaks your game.

Don't want to use Git? Download the .tgz tarball from GitHub Releases and add it via Package Manager.

  1. Go to the Releases page on GitHub.
  2. Under Assets, download CardGameEngine-v6.0.0.tgz.
  3. In Unity, open Window → Package Manager.
  4. Click + → Add package from tarball…
  5. Select the downloaded .tgz file and click Open.
Note: The tarball installs the package into your project's package cache — the same way the Git URL method works. Unlike an older .unitypackage, it does not scatter files into your Assets/ folder.

If you've cloned the repo locally (e.g., to contribute or iterate on the engine itself):

  1. Clone the repository:
    git clone https://github.com/MrPotatomoto/CardGameEngine-Dev.git
  2. In Unity: Window → Package Manager → + → Add package from disk…
  3. Navigate to CardGameEngine-Dev/Packages/com.cardgameengine.core/ and select package.json.
Edit & reload: Any changes you make to the package source are reflected immediately in your Unity project — no reimport step needed.

Quick Start

The minimal example below creates two players, a deck zone, and plays a card from hand to battlefield.

1. Create your data assets

In the Unity Editor, create ScriptableObject assets for your card data:

  • Right-click in the Project window → Create → Card Game Engine → Zone Definition
  • Create a ZoneDefinition named Deck, one named Hand, and one named Battlefield.
  • Create a StatDefinition named Power and one named Toughness.
  • Create a CardDefinition — assign a name, add stats, and reference any abilities.
  • Create a CardTemplate and assign the CardDefinition as its face.

2. Bootstrap the runtime

C# — GameBootstrap.cs 
using UnityEngine;
using CardGameEngine;

public class GameBootstrap : MonoBehaviour
{
    // Assign these in the Inspector
    public ZoneDefinition deckDef;
    public ZoneDefinition handDef;
    public ZoneDefinition battlefieldDef;
    public CardTemplate   cardTemplate;

    void Start()
    {
        // 1. Create the shared game context
        var context = new GameContext();

        // 2. Create players
        var p1 = new Player { DisplayName = "Alice" };
        var p2 = new Player { DisplayName = "Bob" };

        // 3. Create zones and register with ZoneManager
        var deck        = new Zone(deckDef,        p1);
        var hand        = new Zone(handDef,        p1);
        var battlefield = new Zone(battlefieldDef, null); // shared zone

        context.ZoneManager.Register(deck);
        context.ZoneManager.Register(hand);
        context.ZoneManager.Register(battlefield);

        // 4. Create a card instance and add it to the deck
        var card = new CardInstance(cardTemplate, p1, p1);
        deck.TryAdd(card);

        // 5. Draw a card (deck → hand)
        var source = new EffectSource("Draw");
        var draw   = new DrawEffect(source, p1, hand, 1);
        draw.Execute(context);

        // 6. Play the card from hand → battlefield
        var play = new MoveEffect(source, p1, hand.Cards[0], battlefield);
        play.Execute(context);

        Debug.Log($"Battlefield: {battlefield.Count} card(s)");
    }
}
Tip: GameContext is a plain C# object — not a MonoBehaviour. It holds references to all subsystems (ZoneManager, EventBus, ContinuousEffectManager, etc.) and can be created anywhere, making it easy to unit-test your game logic without entering Play Mode.

Core Concepts at a Glance

CardTemplate

ScriptableObject. The permanent definition of a card — art, name, type line, base stats. Never mutated at runtime.

CardInstance

Runtime object. One per physical card in play. Tracks owner, controller, current zone, counters, and any applied continuous effects.

Zone

An ordered list of cards — deck, hand, graveyard, exile, battlefield, etc. Supports add, remove, peek, shuffle, reorder.

IEffect

Discrete unit of game action. Takes a GameContext and returns an EffectResult (Success, Fizzled, Invalid). Composable and testable.

EventBus

Typed pub/sub dispatcher. Publish events like CardEnteredZoneEvent; subscribe anywhere with a lambda. Replacement effects intercept before resolution.

TargetRequirement

Declarative constraint — "a creature your opponent controls." Produces a filtered TargetSet and validates legality.
