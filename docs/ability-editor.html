Ability Editor

Build triggered and activated abilities entirely in the Unity Inspector — no code required for common patterns. Color-coded sections, one-click asset creation, and inline validation catch mistakes before you hit Play.

Overview

The Ability Editor is a set of custom Unity Inspector panels that replace the default ScriptableObject drawers for the three most commonly authored assets:

  • TriggeredAbilityDefinition — displayed as WHEN / IF / THEN coloured sections.
  • ActivatedAbilityDefinition — displayed as COSTS / EFFECT / TIMING sections.
  • SequenceEffectDefinition — displayed as a reorderable step chain with a one-line summary.

Every reference field has a Create & Assign or Create & Add button beside it. Clicking the button opens a context menu that lists every concrete subtype of the required base class, discovered automatically using Unity's TypeCache. Selecting an entry creates the new asset in the same folder as the ability being edited and links it immediately — no manual asset creation or drag-and-drop required.

Triggered ability inspector

Select a TriggeredAbilityDefinition asset in the Project window to see its structured inspector. The panel is divided into four colour-coded sections:

SectionColorFieldNotes
WHENBlueEvent Filter (EventFilterDefinition)Required. A red error banner appears if unassigned — the ability will never fire without it.
IFAmberCondition (ConditionDefinition)Optional. When absent, an italic note reads "no condition — triggers on event match alone."
THENGreenEffect (EffectDefinition)Required. A red error banner appears if unassigned — the ability does nothing without it.
Stack behaviourPurpleBypasses Stack toggleWhen enabled, the effect resolves immediately without going on the stack.

Each reference field is displayed next to a Create & Assign button. Clicking it opens a context menu listing every EventFilterDefinition, ConditionDefinition, or EffectDefinition subtype in the project. Selecting one creates the asset and links it immediately.

Reading the inspector at a glance: If WHEN or THEN shows a red banner, the ability is incomplete and won't work correctly at runtime. The IF section's italic note is informational only — a triggered ability without a condition is perfectly valid.

Activated ability inspector

Select an ActivatedAbilityDefinition asset to see its three-section inspector:

COSTS section (orange)

Displays a reorderable list of AbilityCost assets — all costs must be payable simultaneously for the ability to activate. Each row shows the cost object reference. Null slots are highlighted with a red background and a "(null cost)" label — they'll cause the ability to silently fail at runtime.

An amber warning banner appears when the list is empty: "No costs configured — this ability is free to activate. Verify this is intentional." Free abilities are rare and usually a mistake.

The Create & Add Cost button at the bottom of the section opens a context menu of every concrete AbilityCost subtype (e.g. TapCostDefinition, CompositeCostDefinition), creates the asset, and appends it to the list.

EFFECT section (green)

A single object-reference field for the EffectDefinition that fires on activation. The Create & Assign button opens the full subtype menu for all EffectDefinition types. A red error banner appears if the field is unassigned.

TIMING & STACK section (purple)

Two fields: the ActivationTiming enum (controls which phases/steps the ability can be activated) and the Bypasses Stack toggle.

Sequence effect inspector

Select a SequenceEffectDefinition asset to see its step chain inspector. A SequenceEffectDefinition holds an ordered array of EffectDefinition references that execute in sequence — useful for multi-step card effects like "deal 2 damage, then draw a card."

Summary strip

A one-line chain summary appears below the section header showing every step's type name connected by arrows, e.g.:

Inspector summary 
Deal Damage  →  Draw Card  →  ✕ null

Null slots appear as ✕ null in the summary, and an amber banner below counts how many null steps exist. An empty sequence shows a warning banner: "No steps — this sequence effect does nothing."

Reorderable list

Each step in the list shows an index number chip on the left and the EffectDefinition reference field on the right. Null slots are highlighted red with an italic "(null — will be skipped)" label. You can drag rows to reorder steps, use the standard remove button to delete steps, or drag existing assets from the Project window onto the field.

Create & Add Step

The Create & Add Step button at the bottom opens a context menu of all concrete EffectDefinition subtypes. Selecting one creates the asset in the same folder and appends it as the last step in one action.

How "Create & Assign" works

Under the hood, all the creation buttons use TypeCache.GetTypesDerivedFrom<T>() to discover every concrete, non-abstract subtype of the target base class in the entire project. The type names are formatted for readability (e.g. DrawCardEffectDefinition → "Draw Card Effect"), then displayed as a GenericMenu.

When you select an entry:

  1. A new ScriptableObject of that type is created.
  2. Its path is generated next to the current asset using AssetDatabase.GenerateUniqueAssetPath — no naming conflicts.
  3. The asset is registered with AssetDatabase.CreateAsset.
  4. The serialized property is set to the new asset and changes are applied immediately.

The result: a single click goes from "I need an effect" to "effect asset created, named, and linked."

No-code workflow example

Here's how to build "When this creature enters the battlefield, deal 1 damage to each opponent" entirely in the Inspector:

  1. Create a TriggeredAbilityDefinition asset: Create → Card Game Engine → Abilities → Triggered Ability.
  2. In the WHEN section, click Create & Assign → select Zone Entry Event Filter. Configure it to watch for "enters battlefield."
  3. In the IF section, leave it empty — no condition needed.
  4. In the THEN section, click Create & Assign → select Deal Damage Effect. Configure amount = 1, target = each opponent.
  5. Add the TriggeredAbilityDefinition to your card's CardDefinition abilities list.

No C# required for this pattern. The Inspector's error banners will warn you if any required field is missing before you run the game.
