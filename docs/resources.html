Resources

A flexible, type-safe resource system for mana, gold, energy, or any game currency — with subtype pools, reservations for deferred cost payment, and a unified change event.

Overview

The resource system is built around three ScriptableObjects and two runtime classes:

  • ResourceType — defines a currency: name, pool behaviour, and optional subtypes.
  • ResourceSubtype — a colored or labeled variant (e.g. Red mana, Blue mana).
  • ResourcePool — the live per-player pool for one ResourceType.
  • ResourceManager — the single point of access; all mutations go through it so events fire and reservations are respected.
  • ReservationToken — a lock placed on resources that are committed to a stack entry awaiting resolution.

ResourceType

Create via Create → Card Game Engine → Resources → Resource Type. Each ResourceType asset describes one currency and governs how its pool behaves.

PropertyDescription
ResourceNameDisplay name, e.g. "Mana", "Gold", "Energy".
AbbreviationShort label for UI, e.g. "G" or "⚡".
Color / IconVisual presentation in UI.
StartingAmountHow much each player's pool begins with when initialized.
HasMaximum / MaximumWhen enabled, Add and Set are clamped to this ceiling.
PersistsBetweenTurnsIf false, the pool resets to zero at the start of the owner's turn. Set true for persistent resources like gold.
SubtypesOptional ResourceSubtype[] — leave empty for generic resources.

ResourceSubtype

Create via Create → Card Game Engine → Resources → Resource Subtype. Subtypes let a single ResourceType hold separate named buckets — for example a Mana type could have Red, Blue, Green subtypes.

All mutations on a pool accept an optional subtype parameter. Passing null targets the untyped (generic) bucket. A pool's Total property sums all typed buckets plus the untyped bucket.

Simple games: If your game has a single generic resource (gold, energy, action points) you don't need subtypes at all. Just leave the Subtypes array empty and omit the optional parameter on all ResourceManager calls.

ResourceManager

Access via context.ResourceManager. All reads and writes go through here — never mutate ResourcePool directly.

Pool setup

C# — Initializing a player's mana pool 
// Called once per player at game start (e.g. in SetupPlayerResources).
context.ResourceManager.GetOrCreatePool(player, manaType);

// Give the player 5 generic mana to start.
context.ResourceManager.Add(player, manaType, 5);

// Or add 3 Red mana specifically.
context.ResourceManager.Add(player, manaType, 3, redSubtype);

Mutations

MethodDescription
Add(player, type, amount, subtype?)Increases the pool. Clamped to Maximum if set. Fires ResourceChangedEvent.
TrySpend(player, type, amount, subtype?)Deducts the amount. Returns false (no change) if the available amount (after reservations) is insufficient.
Set(player, type, amount, subtype?)Sets the pool to an exact value. Clamped to [0, Maximum]. Fires ResourceChangedEvent only if the value changes.
OnTurnStart(player)Resets all non-persistent pools for this player to zero. Call at the start of the player's turn before granting new resources.

Queries

MethodDescription
GetAmount(player, type, subtype?)Total amount in the pool — includes reserved amounts.
GetAvailableAmount(player, type, subtype?)Amount available to spend right now — total minus active reservations.
GetOrCreatePool(player, type)Returns (or creates) the ResourcePool for this player/type pair.
GetPool(player, type)Returns the pool, or null if not yet created.

Turn-start resource grant

The most common pattern is to reset non-persistent resources then grant new ones at the start of each turn. Wire this up in your GameBootstrapper:

C# — Auto-action on the Draw phase 
// Subscribe to TurnStartedEvent and reset+refill the active player's mana.
context.EventBus.Subscribe<TurnStartedEvent>(e =>
{
    context.ResourceManager.OnTurnStart(e.ActivePlayer);
    context.ResourceManager.Add(e.ActivePlayer, manaType, 10); // grant 10 mana
});

Reservations

When a spell uses OnResolution cost payment, resources need to be locked at declaration time so the player cannot spend them on something else before the spell resolves. The reservation system handles this transparently.

MethodDescription
TryReserve(player, type, amount, subtype?)Locks the specified amount. Returns a ReservationToken on success, or null if funds are insufficient. The reserved amount is excluded from GetAvailableAmount.
CommitReservation(token)Deducts the reserved amount from the pool and invalidates the token. Called by GameStateMachine when the stack entry resolves.
ReleaseReservation(token)Frees the lock without spending. Called when the stack entry fizzles or is countered.

You rarely need to call these directly — PendingAction.TryCommit() reserves resources automatically for OnResolution entries and attaches the tokens to the StackEntry. GameStateMachine commits or releases them during resolution.

C# — Manual reservation (advanced) 
// Lock 3 mana while a spell is on the stack.
ReservationToken token = context.ResourceManager.TryReserve(player, manaType, 3);
if (token == null)
{
    // Insufficient funds — abort.
    return;
}

// Later: spell resolves.
context.ResourceManager.CommitReservation(token);

// Or: spell fizzles / is countered.
context.ResourceManager.ReleaseReservation(token);

ResourceChangedEvent

Fires after every Add, TrySpend, Set, and reservation commit/release that changes a pool's actual value. Subscribe to update resource displays:

C# — Updating a resource UI bar 
context.EventBus.Subscribe<ResourceChangedEvent>(e =>
{
    if (e.Player != localPlayer || e.ResourceType != manaType) return;

    manaBar.SetValue(e.NewAmount);
    manaLabel.text = $"{e.NewAmount} {manaType.ResourceName}";

    // e.OldAmount, e.Delta, e.Operation (Add / Remove / Set) also available
});
PropertyDescription
PlayerThe player whose pool changed.
ResourceTypeWhich resource type was affected.
SubtypeThe subtype bucket, or null for the untyped bucket.
OldAmount / NewAmountPool values before and after the change.
DeltaShorthand for NewAmount - OldAmount.
OperationResourceOperation.Add, Remove, or Set.
