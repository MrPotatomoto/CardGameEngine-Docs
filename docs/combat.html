Combat

The CombatManager handles attacker declarations, blocker declarations, and multi-step damage resolution including first strike and trample.

Overview

CombatManager is accessed via context.CombatManager. It tracks which cards are attacking or blocking and resolves damage through the ReplacementEffectLayer — so prevention and redirection effects work automatically, exactly as they do for DealDamageEffect.

Setup

Before using combat, configure the stat assets the manager reads from:

C# — Configuring CombatManager 
// Wire up in GameBootstrapper.OnGameSetupComplete (or equivalent)
var combat = context.CombatManager;

combat.PowerStat        = powerStatDefinition;      // how much damage attackers/blockers deal
combat.DamageStat       = toughnessStatDefinition;  // what damage is subtracted from
combat.CombatDamageType = combatDamageType;         // optional — typed damage (e.g. "combat")

// Optional keyword flags (CardStateFlag assets)
combat.TrampleFlag      = trampleFlag;
combat.FirstStrikeFlag  = firstStrikeFlag;
combat.DoubleStrikeFlag = doubleStrikeFlag;
Note: CombatManager does not enforce summoning sickness or flying. Plug in CanAttackFilter and CanBlockFilter delegates to add game-specific restrictions without subclassing.

Combat flow

A typical combat phase runs in five steps:

1. Declare attackers

C# — Declaring attackers 
if (context.CombatManager.TryDeclareAttacker(goblin, defendingPlayer, out var reason))
    Debug.Log("Goblin is attacking!");
else
    Debug.LogWarning($"Cannot attack: {reason}");

On success, an AttackerDeclaredEvent is published. You can subscribe to this to apply a "tapped while attacking" flag or trigger other effects.

2. Declare blockers

C# — Declaring blockers 
// Get the CombatAttacker record for the card being blocked
var attacker = context.CombatManager.GetAttacker(goblin);

context.CombatManager.TryDeclareBlocker(knight, attacker, out var reason);

Multiple creatures can block the same attacker. Damage is assigned to blockers in the order they were declared.

3. First-strike damage (optional)

Call this step only when at least one attacking or blocking creature has FirstStrikeFlag or DoubleStrikeFlag set. Skip it entirely for simpler games.

C# 
var source = new EffectSource(Guid.NewGuid(), "Combat");
context.CombatManager.ResolveCombatDamage(source, isFirstStrike: true);

4. Normal damage

C# 
context.CombatManager.ResolveCombatDamage(source, isFirstStrike: false);

5. End combat

C# 
context.CombatManager.EndCombat(source);
// Fires CombatEndedEvent. Subscribe here to untap attackers, etc.

Trample

When an attacker has the TrampleFlag, any excess damage beyond what is needed to kill all blockers carries over to the defending player. The manager assigns damage in declaration order, stopping at the lethal amount for each blocker, then sends the remainder to the player.

Attack and block restrictions

Use the filter delegates to implement game rules like summoning sickness or flying without subclassing:

C# — Summoning sickness 
combat.CanAttackFilter = (attacker, defender, ctx) =>
{
    if (attacker.HasFlag(summoningSicknessFlag))
        return "This creature has summoning sickness and cannot attack.";
    return null; // null = allow
};

combat.CanBlockFilter = (blocker, attackerRecord, ctx) =>
{
    // Flying: only flying creatures can block flying attackers
    bool attackerFlying = attackerRecord.Card.HasFlag(flyingFlag);
    bool blockerFlying  = blocker.HasFlag(flyingFlag)
                       || blocker.HasFlag(reachFlag);

    if (attackerFlying && !blockerFlying)
        return "Only flying or reach creatures can block flying attackers.";

    return null;
};

Combat events

EventWhen
AttackerDeclaredEventTryDeclareAttacker succeeds.
AttackerRemovedEventRemoveAttacker is called.
BlockerDeclaredEventTryDeclareBlocker succeeds.
BlockerRemovedEventRemoveBlocker is called.
CombatDamageStepStartedEventStart of each damage step.
CombatDamageStepEndedEventEnd of each damage step.
CombatEndedEventEndCombat is called.
