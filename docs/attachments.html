Attachments

Model equipment, auras, and any card-to-card bond with AttachmentManager, AttachEffect, and DetachEffect.

Overview

An attachment is a card that is logically bonded to a host card. Equipment, auras, fortifications — anything where card A modifies card B while both are in play — uses this system.

AttachmentManager lives at context.AttachmentManager. It keeps two dictionaries: one mapping each attachment to its current host, and one mapping each host to the list of cards attached to it.

You never call AttachmentManager directly from game code. Instead, use the provided effects:

  • AttachEffect — attach one card to another.
  • DetachEffect — remove an attachment from its host.

Attaching a card

C# — Equipping a sword to a creature 
var source = new EffectSource(swordCard);
var attach = new AttachEffect(source, controller, attachment: swordCard, host: goblinCard);
attach.Execute(context);
// Fires CardAttachedEvent(source, swordCard, goblinCard)

If the sword is already equipped to a different creature, AttachEffect automatically detaches it from the previous host first — the standard re-equip behaviour.

Detaching

C# — Detaching 
var detach = new DetachEffect(source, controller, swordCard);
detach.Execute(context);
// Fires CardDetachedEvent(source, swordCard, previousHost)

Querying attachment state

C# 
var mgr = context.AttachmentManager;

// Is this card equipped to something?
bool equipped = mgr.IsAttached(swordCard);

// What is it attached to?
CardInstance host = mgr.GetHost(swordCard);

// What is attached to this creature?
IReadOnlyList<CardInstance> gear = mgr.GetAttachments(goblinCard);

Attachment fall-off

AttachmentManager does not automatically detach cards when a host moves zones — that is a game-rule concern, not a core mechanism. The engine ships a ready-made state-based action to handle it:

C# — Registering the fall-off SBA 
// attachmentFallOffSBA is a pre-configured AttachmentFallOffSBA ScriptableObject.
// It checks whether a host is still in an "active" zone (AbilitiesActive = true).
// If the host has left, it strips all attachments.

context.StateBasedActionManager.Register(attachmentFallOffSBA);

Create the SBA asset via Create → Card Game Engine → Rules → Attachment Fall-Off SBA and set its Active Zone Type to your battlefield zone type. Then register it once at game start. The StateBasedActionManager will call CheckAndResolve() automatically before each priority grant.

Granting stat bonuses

Attachments grant bonuses through the continuous effect system, not through the attachment relationship directly. When a card is attached, subscribe to CardAttachedEvent and apply a StatModifier continuous effect sourced from the attachment. When it is detached, apply an expiry to that effect.

C# — Pattern: equipment grants +2 Power 
context.EventBus.Subscribe<CardAttachedEvent>(e =>
{
    if (e.Attachment != swordCard) return;

    var modifier = new StatModifier(powerDef, 2, e.Source,
        expiresWhen: ExpiryReason.SourceLeavesBattlefield);
    context.ContinuousEffectManager.Apply(modifier, e.Host);
});

context.EventBus.Subscribe<CardDetachedEvent>(e =>
{
    if (e.Attachment != swordCard) return;
    context.ContinuousEffectManager.ExpireFromSource(swordCard);
});
