Core Concepts

Keywords

Data-driven named abilities. Define them once as assets, grant them to cards, and check for them from any system that needs to enforce their effects.

Overview

A keyword in Card Game Engine is a named ability token — a label that carries meaning defined entirely by the systems that read it. The engine has no built-in rules for Flying, Trample, Haste, or any other keyword; it simply provides a clean way to declare that a card has a keyword, and a clean way for systems to ask whether it does.

This separation keeps keywords flexible. The same keyword can influence combat, targeting, SBAs, cost calculations, and tooltip rendering, each system checking independently without the keyword needing to know about any of them.

🏷️

KeywordDefinition

A ScriptableObject that names a keyword and carries reminder text. One asset per keyword.

⚡

KeywordAbility

An IntrinsicAbility that grants a keyword to a card face. Added to a CardDefinition's abilities list.

🔍

HasKeyword()

Available on both CardDefinition and CardInstance. O(n) over intrinsic abilities — fast for typical counts.

📚

KeywordLibrary

An optional project-wide catalog for resolving keywords by name. Needed only for string-based lookups.

KeywordDefinition

Create a KeywordDefinition asset for every keyword in your game. Each asset is a stable identity — card data references the asset directly, not a string name.

Create via: Assets → Create → Card Game Engine → Keyword

FieldTypePurpose
KeywordName string Display name printed on the card and used as the lookup key in KeywordLibrary. E.g. "Flying".
ReminderText string Rules reminder shown in parentheses on the card. E.g. "This creature can only be blocked by creatures with flying or reach."
ShortCode string Compact identifier for UI badges. Falls back to KeywordName if left blank.
IsEvergreen bool Flag for evergreen keywords (appear across many sets). Used by tooltip renderers and search UIs — no engine behavior.

The FormatReminderLine() helper returns "Flying (This creature can only be blocked by...)" if reminder text is set, or just "Flying" if not — convenient for tooltip renderers.

var line = flyingDef.FormatReminderLine();
// → "Flying (This creature can only be blocked by creatures with flying or reach.)"

KeywordAbility

A KeywordAbility is a ScriptableObject asset that links a KeywordDefinition to a card face. It extends IntrinsicAbility, which is the base class for all static, always-on abilities defined in CardDefinition.

Create via: Assets → Create → Card Game Engine → Abilities → Keyword Ability

Once created, assign the KeywordDefinition in the Inspector, then add the KeywordAbility asset to a CardDefinition's Intrinsic Abilities array:

  1. Create a KeywordDefinition asset: Card Game Engine → Keyword
  2. Create a KeywordAbility asset: Card Game Engine → Abilities → Keyword Ability
  3. In the KeywordAbility Inspector, set Keyword to your definition asset.
  4. Open a CardDefinition and add the KeywordAbility to the Intrinsic Abilities list.
Tip: KeywordAbility assets are reusable. Create one Flying ability asset and share it across every card that flies — you don't need a separate ability asset per card.

Checking for a keyword

Two HasKeyword methods are available depending on whether you have a card definition or a live instance:

MethodSourceNotes
CardDefinition.HasKeyword(KeywordDefinition) Static card data Checks the definition's IntrinsicAbilities array. Useful when you don't have a live instance yet, or when checking the printed keyword independent of face state.
CardInstance.HasKeyword(KeywordDefinition) Live card in play Delegates to CurrentFace.HasKeyword(). Automatically accounts for face-down cards, transformed cards, and any other face-switching. Prefer this at runtime. 
// Checking a live card in play (preferred at runtime):
bool hasFlying = attacker.HasKeyword(_flyingDefinition);

// Equivalent long form — same result:
bool hasFlying = attacker.CurrentFace?.HasKeyword(_flyingDefinition) ?? false;

// Checking the card definition directly (e.g. deck validation):
bool hasTrample = template.DefaultFace.HasKeyword(_trampleDefinition);
Why CurrentFace? A double-faced card has two CardDefinition assets — one per face. CardInstance.HasKeyword() reads CurrentFace (the active face index), so a face-down card that loses Flying, or a transformed card that gains Trample, will reflect the correct state automatically.

KeywordLibrary

The KeywordLibrary is an optional catalog asset that lets you resolve a KeywordDefinition by its name string. It is not required for normal combat or ability checks — those use direct asset references. The library is useful when:

  • A rules-text parser needs to find the definition for the word "Flying" in a card's text box.
  • A deck-builder UI needs to filter cards by keyword name typed in a search box.
  • A tooltip renderer wants to look up reminder text for a keyword badge.

Create via: Assets → Create → Card Game Engine → Keyword Library

Lookup is case-insensitive and backed by a lazy dictionary. The cache is rebuilt on first use and invalidated on domain reload.

// Inject via Inspector: [SerializeField] KeywordLibrary _library;

// Resolve by name (returns null if not found):
KeywordDefinition flying = _library.Resolve("Flying");

// Try-resolve pattern:
if (_library.TryResolve("flying", out var def))
    Debug.Log(def.FormatReminderLine());

KeywordLibrary Generator

Rather than manually maintaining the library's keyword list, use the editor generator to auto-populate it from all KeywordDefinition assets in the project.

Workflow:

  1. Select your KeywordLibrary asset in the Project window.
  2. Run Card Game Engine → Generate Keyword Library from the menu bar.
  3. Confirm the dialog. The generator scans every KeywordDefinition in the project, sorts them alphabetically by KeywordName, and writes them into the library.
  4. Re-run any time you add or rename keyword assets.
Tip: The menu item is greyed out when no KeywordLibrary asset is selected. Select the asset first, then run the generator.

The generator replaces all existing entries, so stale references to deleted keyword assets are automatically removed. It also calls InvalidateCache() on the library after writing, so lookups immediately reflect the new data without a domain reload.

Writing a keyword-aware system

Systems that enforce keyword rules receive a KeywordDefinition reference as a [SerializeField] and call HasKeyword() on the relevant cards. No string parsing, no magic constants.

using UnityEngine;
using CardGameEngine;

public class SimpleCombatSystem : MonoBehaviour
{
    [SerializeField] private KeywordDefinition _flying;
    [SerializeField] private KeywordDefinition _reach;
    [SerializeField] private KeywordDefinition _trample;

    /// Returns true if blocker can legally block attacker.
    public bool CanBlock(CardInstance attacker, CardInstance blocker)
    {
        // A flying attacker can only be blocked by flyers or reach creatures.
        if (attacker.HasKeyword(_flying))
            return blocker.HasKeyword(_flying) || blocker.HasKeyword(_reach);

        return true;
    }

    /// Assigns excess combat damage to the defending player when attacker has trample.
    public void AssignCombatDamage(CardInstance attacker, CardInstance blocker,
                                    StatDefinition power, StatDefinition toughness,
                                    Player defender, StatDefinition lifeStat)
    {
        int dmg = attacker.GetStat(power);
        int lethal = blocker.GetStat(toughness);

        if (attacker.HasKeyword(_trample) && dmg > lethal)
        {
            blocker.ModifyStat(toughness, -lethal);
            defender.ModifyStat(lifeStat, -(dmg - lethal));
        }
        else
        {
            blocker.ModifyStat(toughness, -dmg);
        }
    }
}
Pattern: Inject keyword definitions via [SerializeField] and assign them in the Inspector. This keeps your system decoupled from keyword names and makes it easy to unit-test with different keyword assets.
