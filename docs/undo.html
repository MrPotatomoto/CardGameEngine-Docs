Undo & Checkpoints

Roll game state back one action at a time with CheckpointManager and UndoableGameStateMachine. Give players a safety net without writing any snapshot code yourself.

Overview

The undo system is built on top of Serialization. CheckpointManager maintains a rolling stack of GameSnapshot objects in memory. UndoableGameStateMachine is a drop-in subclass of GameStateMachine that automatically pushes a checkpoint before every priority grant — so every player action is automatically revertible.

What each checkpoint captures:

  • Zone contents and per-card state (face, tapped, stats, counters, flags) via GameSerializer.Capture.
  • Resource pool amounts for all players.
  • Turn number, active player index, and timestamp.
  • Player stat values (life totals, poison counters, etc.) — restored directly without firing events.
Known limitations: Registered ContinuousEffects, IReplacementEffects, and triggered-ability registrations are not snapshotted. Effects granted by cards in play are re-established when those cards re-enter active zones, but globally-registered effects must be re-registered by your code after a restore. Also: the stack is not restored — capture checkpoints only when the stack is empty.

Automatic undo with UndoableGameStateMachine

The quickest path to undo: swap GameStateMachine for UndoableGameStateMachine in your bootstrapper. The subclass overrides OnBeforePriorityGrant to call PushCheckpoint() automatically — no changes to your priority callbacks required.

Step 1 — Override CreateStateMachine

C# — GameBootstrapper subclass 
public class MyBootstrapper : GameBootstrapper
{
    private MyAssetResolver _resolver = new MyAssetResolver();

    // 1. Return the undoable subclass instead of the base class.
    protected override GameStateMachine CreateStateMachine(
        TurnStructureDefinition ts,
        IReadOnlyList<Player> players,
        GameContext ctx)
    {
        return new UndoableGameStateMachine(
            ts, players, ctx, ctx.CheckpointManager);
    }

    // 2. Provide the resolver so RestoreSnapshot can rebuild SO assets.
    protected override IGameAssetResolver GetAssetResolver()
        => _resolver;
}

Step 2 — Wire up an Undo button

Call UndoLastAction() from any UI component. It internally calls CheckpointManager.PopCheckpoint(resolver) using the resolver returned by GetAssetResolver().

C# — UI button handler 
// e.g. on a Unity UI Button's onClick event:
public void OnUndoButtonClicked()
{
    bool undone = bootstrapper.UndoLastAction();
    undoButton.interactable = bootstrapper.Context.CheckpointManager.HasCheckpoints;
}

CheckpointManager API

Accessed via context.CheckpointManager. You rarely need to call it directly when using UndoableGameStateMachine, but it's available for manual control.

MemberDescription
MaxDepthMaximum number of checkpoints to retain. Oldest are discarded when the limit is exceeded. Default: 10. Must be ≥ 1.
CountNumber of checkpoints currently held.
HasCheckpointstrue when at least one checkpoint is available.
PushCheckpoint()Captures current state and pushes it onto the stack. Discards the oldest if MaxDepth is exceeded.
PopCheckpoint(resolver)Restores the most recent checkpoint and removes it from the stack. Returns false if the stack is empty or resolver is null.
PeekSnapshot()Returns the most recent GameSnapshot without restoring or removing it. Returns null if empty.
DiscardTop()Removes the most recent checkpoint without restoring it.
Clear()Discards all stored checkpoints.

Manual checkpoints

You can push and pop checkpoints manually — for example, to create a save-before-complex-action pattern that doesn't depend on the priority loop. This is useful for non-interactive steps like AI combos, or for targeting a specific rewind point deeper than one action.

C# — Manual checkpoint example 
var checkpoints = context.CheckpointManager;

// Save before a complex sequence.
checkpoints.PushCheckpoint();

// ... perform several effects ...

// Something went wrong — roll back.
checkpoints.PopCheckpoint(myResolver);

// Change undo depth to allow 20 levels.
checkpoints.MaxDepth = 20;

Undo depth and memory

Each checkpoint is a complete in-memory copy of zone contents and player stats. Memory usage scales with the number of zones, cards, and players. For most games, the default depth of 10 is reasonable. If memory is a concern, reduce MaxDepth before the game loop starts:

C# 
// Single-level undo: only keep the immediately previous state.
context.CheckpointManager.MaxDepth = 1;
Tip: Disable undo for AI turns to avoid accumulating snapshots the player can never trigger. Call checkpoints.DiscardTop() immediately after the AI's priority window closes, or skip pushing altogether by checking whether the active player is human before calling PushCheckpoint.
