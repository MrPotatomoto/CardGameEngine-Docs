Node Graph Editor

Visualize and rewire your entire ability tree as a zoomable node canvas. See how an event filter connects to a triggered ability, which conditions guard it, and exactly what effects fire when it resolves — all in one view.

Overview

The Ability Graph window renders any TriggeredAbilityDefinition, ActivatedAbilityDefinition, or SequenceEffectDefinition as a tree of connected nodes. Each ScriptableObject in the asset-reference chain becomes one node; serialized object-reference fields become output ports with bezier wires drawn to the referenced asset's node.

The window reads the existing ScriptableObject graph — no separate data format or additional assets are created. Rewiring a connection in the graph updates the underlying serialized property, exactly as if you had used the object picker in the Inspector.

Complement, don't replace: The graph window excels at navigation and wiring overview. For creating new assets, configuring per-field parameters (damage amounts, zone filters, etc.), and adding array elements, continue using the structured Ability Editor inspectors — they show the same fields with richer validation and one-click asset creation.

Opening the window

Three ways to open the Ability Graph:

  • Menu: Window → Card Game Engine → Ability Graph
  • Right-click: right-click any TriggeredAbilityDefinition, ActivatedAbilityDefinition, or SequenceEffectDefinition asset in the Project window and choose Card Game Engine → Open in Ability Graph
  • Auto-open: while the window is open, selecting a supported asset in the Project window automatically loads it — no extra clicks required

Node anatomy

Each node has two regions:

  • Header band — shows the asset's type name (formatted, e.g. "Deal Damage") and below it the asset's file name. The header is color-coded by base type (see color table below). A grey dot on the left edge marks the input port — the point where wires from parent nodes arrive.
  • Port rows — one row per output port. Each row shows the field label on the right and a colored dot on the right edge. A bright dot indicates the slot is connected; a dim grey dot indicates it is empty (null reference). Drag from a bright or dim output dot to start rewiring.

Port dot colors

Output port dots inherit the color of the type they accept — a green dot on a "Then" port means it expects an EffectDefinition, a blue dot on "Event Filter" expects an EventFilterDefinition, and so on. Dim grey always means unconnected regardless of type.

Rewiring connections

To change which asset a port points to:

  1. Hover over the output dot on the right edge of the port row — the cursor changes to indicate it is draggable.
  2. Click and drag from the dot. A yellow bezier wire follows the mouse.
  3. Release over any node whose asset type is compatible with the port (e.g., drag an "Effect" port onto any EffectDefinition node).
  4. The serialized reference is updated immediately via SerializedObject.ApplyModifiedProperties and the graph rebuilds.

Press Esc while dragging to cancel without making any change.

Array ports are view-only for adding elements: ports labeled "Steps 0", "Steps 1", etc. can be reassigned by dragging — this swaps which asset sits at that array index. But you cannot add or remove array elements through the graph. Use the Sequence Effect inspector's "Create & Add Step" button, or the standard Unity array controls in the default inspector, to change the array length.

Selecting and inspecting nodes

  • Click a node — selects it and sets Selection.activeObject, so the Inspector updates to show that asset's fields.
  • Double-click a node — pings the asset in the Project window, flashing its location in the folder tree.
  • Right-click empty canvas — context menu with Select Root in Inspector, Fit to Window, Reset Layout, and Refresh Graph.

Layout and persistence

The first time a root asset is opened, the window runs an automatic tree layout: the root node starts at the top-left and child nodes are placed to the right in columns, stacked vertically within each column. The layout is a depth-first tree — shared assets referenced from multiple ports appear at their first-encountered position.

After you drag nodes to preferred positions, those positions are saved to EditorPrefs keyed by the root asset's GUID. Positions survive domain reloads, Unity restarts, and closing/reopening the window. They are machine-local and are not stored in the project's version control.

Click Reset Layout in the toolbar to clear saved positions and re-run the automatic layout at any time.

Typical workflow

  1. Create ability assets using the Ability Editor inspector's "Create & Assign" buttons. The graph is automatically populated from the references those buttons set.
  2. Open the Ability Graph window. Select the root TriggeredAbilityDefinition or ActivatedAbilityDefinition in the Project window — the graph loads automatically.
  3. Read the graph top-to-bottom: left column is the ability root, middle columns are effects and conditions, rightmost columns are leaf values.
  4. To swap which effect fires for a branch (e.g., change a Conditional's Then branch), drag from the "Then" output dot onto the replacement EffectDefinition node.
  5. Switch back to the Inspector (click the node, or use the right-click menu) to configure per-field parameters on the newly-wired asset.
  6. Press F at any time to re-center the view.
