Deck Management

Build deck lists in the Inspector with DeckDefinition, deal opening hands with full mulligan support via MulliganSystem, and implement tutor effects with SearchEffect.

DeckDefinition

DeckDefinition is a ScriptableObject that holds an Inspector-editable list of cards and copy counts. Create one via Create → Card Game Engine → Deck Definition.

Each entry in the list is a DeckEntry — a CardTemplate reference and a copy count (minimum 1). The order of entries determines the initial zone order before shuffling.

Populating a library zone

Call Populate from your GameBootstrapper after creating your zones. It instantiates one CardInstance per entry × count and transfers each into the zone via ZoneManager.Transfer, firing CardEnteredZoneEvent for each card.

C# — GameBootstrapper.SetupPlayerResources 
protected override void SetupPlayerResources(Player player, GameContext ctx)
{
    var library = ctx.ZoneManager.GetZone(_libraryDefinition, player);
    _deckDefinition.Populate(library, owner: player, controller: player, ctx);
    // Shuffle happens later in MulliganSystem — or call library.Shuffle() here
}
Tip: Entries with a null template or a count ≤ 0 are silently skipped. Use DeckDefinition.TotalCardCount to verify the total before play begins.

MulliganSystem

MulliganSystem handles the opening-hand ritual: shuffle the library, deal an opening hand, and offer players mulligans until they keep or exhaust their allowance.

Setup

C# — Wiring up MulliganSystem 
// 1. Subscribe to the mulligan offer event before calling RunOpeningHands.
Context.ReplacementEffectLayer.Process(new MulliganOfferedEvent(...)); // handled internally

context.EventBus.Subscribe<MulliganOfferedEvent>(e =>
{
    // Show UI to the player, then call Keep or Mulligan on the state object.
    bool wantsToMulligan = ShowMulliganUI(e.State.Hand, e.State.CardsInNextHand);
    if (wantsToMulligan)
        e.State.Mulligan();   // return entire hand
    else
        e.State.Keep();
});

// 2. Create the system and run it.
var mulliganSystem = new MulliganSystem(openingHandSize: 7, maxMulligans: 7);
mulliganSystem.DrawTag         = drawTransferTag;     // optional — identifies draws
mulliganSystem.MulliganReturnTag = mulliganReturnTag; // optional

mulliganSystem.RunOpeningHands(players, context, _libraryDefinition, _handDefinition);

MulliganState

The event carries a MulliganState object that your subscriber uses to record the player's decision:

MemberDescription
PlayerThe player being offered the mulligan.
HandSnapshot of current hand cards.
MulliganNumber0 = first offer; 1 = after first mulligan; etc.
CardsInNextHandHow many cards they would draw if they mulligan now.
Keep()Accept this hand. The mulligan sequence ends.
Mulligan()Return entire hand to library, draw fewer cards.
Mulligan(cardsToReturn)Return a specific subset of cards (partial mulligan variant).

Mulligan variants

The default hand-size reduction is Vancouver rules (draw one fewer per mulligan). Override the delegate to use other schemes:

C# — London mulligan (always draw 7) 
// London: always draw 7, but after keeping the player puts back N cards.
// (The "put back" step is a separate mechanic your game layer handles.)
mulliganSystem.HandSizeAfterMulligan = n => 7;

// Flat -2 per mulligan
mulliganSystem.HandSizeAfterMulligan = n => Math.Max(0, 7 - n * 2);

DeckFormatDefinition

Create via Create → Card Game Engine → Deck Format Definition. A DeckFormatDefinition asset declares the construction rules for a format. Pass it to DeckDefinition.Validate() to check legality.

FieldDescription
FormatNameDisplay name, e.g. "Standard", "Commander", "Draft".
MinDeckSizeMinimum total card count. 0 = not enforced. Default: 60.
MaxDeckSizeMaximum total card count. 0 = not enforced.
MaxCopiesOfAnyCardMax copies of a single template. 0 = unlimited. Default: 4. Duplicate entries for the same template are summed before checking.
EnforceSetConstraintsWhen true, every card's set must appear in AllowedSets.
AllowedSetsThe legal SetDefinition assets for this format.

Validating a deck

DeckDefinition.Validate(format) returns a list of DeckViolation objects — one per broken rule. An empty list means the deck is legal.

C# — Checking legality before a match 
var violations = _deckDefinition.Validate(standardFormat);

if (violations.Count == 0)
{
    StartMatch();
}
else
{
    foreach (var v in violations)
        errorPanel.AddLine(v.Description);  // human-readable message
}

DeckViolation

PropertyDescription
TypeTooFewCards, TooManyCards, TooManyCopiesOfCard, or CardNotInAllowedSet.
DescriptionReady-to-display message, e.g. "Deck contains 55 cards; minimum for this format is 60."
OffendingTemplateThe specific card that broke a per-template rule, or null for size violations.
ActualCountThe count that triggered the violation.
AllowedCountThe limit that was exceeded (or required minimum for TooFewCards).

SideboardDefinition

Create via Create → Card Game Engine → Sideboard Definition. A sideboard is a companion list of cards that can be swapped into the main deck between games in a match.

PropertyDescription
EntriesThe sideboard cards and their copy counts (IReadOnlyList<DeckEntry>).
MaxSizeOptional maximum total card count enforced by the asset. Default: 15. Set to 0 for no asset-level limit.
TotalCardCountSum of all valid entry counts.

BetweenGamesManager

BetweenGamesManager owns the between-game sideboard ritual. It keeps a mutable working copy of the deck and sideboard, applies and reverts swaps, validates the combined configuration, and populates the library zone for the next game — all without touching any live Zone or CardInstance objects.

Typical workflow

C# — Between-game sideboard session 
// 1. Create a manager after each game ends.
var manager = new BetweenGamesManager(_deckDefinition, _sideboardDefinition);

// 2. Display the current deck and sideboard to the player.
ShowSideboardUI(manager.GetActiveMainDeckEntries(),
                manager.GetActiveSideboardEntries());

// 3. Apply a swap: bring 2 CounterSpells from side, send 2 Fireballs to side.
if (!manager.TrySwap(counterSpellDef, fireballDef, 2, out string error))
    ShowError(error);

// 4. Optionally validate the final configuration.
var violations = manager.Validate(standardFormat);

// 5. At game start, populate the library with the swapped deck
//    (call this instead of DeckDefinition.Populate).
manager.PopulateMainDeck(library, owner: player, controller: player, context);
library.Shuffle();

BetweenGamesManager API

MemberDescription
TrySwap(sideCard, mainCard, count, out error)Exchanges count copies of sideCard into the main deck for count copies of mainCard. Returns false with a human-readable error if either side lacks sufficient copies.
RevertLastSwap()Undoes the most recent swap. Returns false if no swaps have been made.
RevertAllSwaps()Resets both the deck and sideboard to their original asset state.
GetActiveMainDeckEntries()Snapshot of the current main deck after all applied swaps.
GetActiveSideboardEntries()Snapshot of the current sideboard.
SwapLogRead-only list of every swap applied this session, most recent last.
Validate(format)Full validation — deck size, sideboard size, copy limits, set legality. Returns a combined DeckViolation list.
PopulateMainDeck(zone, owner, controller, ctx)Creates CardInstances from the active main deck and transfers them into the zone. Use in place of DeckDefinition.Populate() when sideboard swaps are active.
Total card count is preserved: Every swap exchanges equal numbers of cards, keeping the main deck size constant across swaps. Validation still catches size violations from the original asset or format changes.

SearchEffect — Library Search (Tutor)

SearchEffect implements the "search your library for a card" mechanic. It collects eligible cards from the library, fires a LibrarySearchStartedEvent so your UI can present the choice, moves the chosen card to the destination zone, shuffles the library, and fires LibrarySearchCompletedEvent.

C# — "Search for a creature, put it into your hand" 
// 1. Subscribe to the search event to show UI and record the choice.
context.EventBus.Subscribe<LibrarySearchStartedEvent>(e =>
{
    // e.State.Candidates is the filtered list the player can pick from.
    CardInstance chosen = ShowSearchUI(e.State.Candidates, e.State.SearchingPlayer);
    if (chosen != null)
        e.State.Choose(chosen);
    else
        e.State.ChooseNone();
});

// 2. Create and execute the effect.
var search = new SearchEffect(
    source:      mySource,
    controller:  activePlayer,
    library:     playerLibrary,
    destination: playerHand,
    filter:      _creatureFilter,     // null = all cards eligible
    transferTag: _searchTag,          // optional — tags the zone transfer
    shuffleAfterSearch: true);       // default: true

var result = search.Execute(context);
// result.Status == EffectStatus.Success  — card fetched
// result.Status == EffectStatus.Partial  — searched but nothing chosen

SearchState

The event carries a SearchState object:

MemberDescription
CandidatesAll cards in the library that passed the filter.
LibraryThe zone being searched.
SearchingPlayerThe player performing the search (who can see the cards).
Choose(card)Select a card to fetch. Does not need to be in Candidates — the effect validates it is still in the library.
ChooseNone()Intentionally find nothing (fail-to-find).
Note: If no subscriber commits a decision, SearchEffect defaults to ChooseNone(). The library is still shuffled. This prevents library-order information leaks even when a search fails.
