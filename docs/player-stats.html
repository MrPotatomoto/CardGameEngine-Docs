Player Stats

Track life totals, poison counters, energy, and any other numeric player resource with PlayerStatManager and PlayerStatDefinition.

Overview

Card stats (power, toughness) live on CardInstance and are modified by continuous effects. Player stats are different — they are independent numeric values owned by players, not cards. Life totals, poison counters, and energy counters are classic examples.

PlayerStatManager is accessed via context.PlayerStatManager. Every write goes through the replacement-effect layer, so damage prevention and other interceptors work automatically.

Defining a player stat

Create a PlayerStatDefinition asset: Create → Card Game Engine → Definitions → Player Stat.

Key inspector fields:

  • Stat Name — display name (e.g. "Life", "Poison").
  • Starting Value — initial value when a player is initialised (e.g. 20 for life).
  • Min Value / Max Value — clamping bounds. Set Max Value to a very large number if there is no upper cap.

Initialising players

Call Initialize for each player before the game loop starts. This seeds their stats at StartingValue.

C# — Setup 
// lifeStatDef.StartingValue = 20, poisonStatDef.StartingValue = 0
context.PlayerStatManager.Initialize(player1, new[] { lifeStatDef, poisonStatDef });
context.PlayerStatManager.Initialize(player2, new[] { lifeStatDef, poisonStatDef });

Reading a stat

C# 
int life = context.PlayerStatManager.GetStat(player1, lifeStatDef);
Debug.Log($"{player1.DisplayName} has {life} life.");

Modifying a stat

C# — Dealing player damage / gaining life 
var statMgr = context.PlayerStatManager;
var source  = new EffectSource(Guid.NewGuid(), "Lava Spike");

// Deal 3 damage to player (subtract from life)
statMgr.ModifyStat(player1, lifeStatDef, delta: -3, source);

// Set life to a specific value
statMgr.SetStat(player1, lifeStatDef, newValue: 1, source);

// Gain 4 life
statMgr.ModifyStat(player1, lifeStatDef, delta: +4, source);

All writes are clamped to the stat's configured bounds and fire a PlayerStatChangedEvent through the replacement-effect layer. Replacement effects (like damage prevention) can intercept and modify the change before it is applied.

Events

EventWhenKey fields
PlayerStatChangedEventAny successful write that changes the value.Player, Stat, OldValue, NewValue

SBA integration — player elimination

The engine ships a PlayerEliminationSBA that checks whether a player's stat has reached the configured minimum. Register it to automatically eliminate players at 0 life:

C# — Player elimination SBA 
// playerEliminationSBA is a PlayerEliminationSBA ScriptableObject.
// Configure: Stat = lifeStatDef, Elimination Threshold = 0.
context.StateBasedActionManager.Register(playerEliminationSBA);

// Subscribe to know when a player is eliminated
context.EventBus.Subscribe<PlayerEliminatedEvent>(e =>
{
    Debug.Log($"{e.Player.DisplayName} has been eliminated!");
    // trigger game-over or remove the player from the turn order
});

Create the SBA asset via Create → Card Game Engine → Rules → Player Elimination SBA.
